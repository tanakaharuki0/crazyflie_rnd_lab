# tof_odometry.py — グラフの読み方

超低密度ToF点群（VL53L8CX 4x4 = 16点/センサー）から移動量 Δt・回転量 ΔR を推定する
`tof_odometry.py` の出力グラフについて、各パネルの意味と読み取り方をまとめる。

アルゴリズムの出典は `docs/Drone Sparse ToF Odometry Research` の 3章
（3.1 平面抽出 / 3.2 Kabsch による ΔR / 3.3 Point-to-Plane による Δt）。

## 使い方

```bash
# log41.csv に対して sensor 0,1,2 で実行 (既定)
python3 tof_odometry.py log41.csv

# センサーを指定し、推定結果もCSVに出す
python3 tof_odometry.py log41.csv -s 0 1 2 --csv-out csv/log41_odom.csv
```

出力は `figs/<ログ名>_tof_odometry.png`（4行×2列の8パネル）。
横軸はすべて共通で、ログ先頭を 0 とした経過時間 [s] である。

---

## 前処理：点群の生成

各パネルの前提として、16ゾーンの距離値は以下の手順でボディ座標系の3D点に変換されている。

1. ゾーン番号 `i` → 格子位置 `row = i//4, col = i%4`。`depth_map.py` と同じく上下左右を
   反転して物理的な向き（row↑ = 上、col↑ = 左）に直す。
2. FOV 45°（4x4 なので 1ゾーン 11.25°）から各ゾーン中心の視線単位ベクトルを作り、
   距離を掛けてセンサー座標の点にする（光軸 +x、+y 左、+z 上）。
3. `docs/vl53l8cx-position.md` の取り付け位置 [mm] と yaw/pitch/roll でボディ座標系へ変換。
4. 距離が 30〜4000 mm の範囲外、または欠損のゾーンは除外。

**注意**: log39〜41 には `st0..st15`（target_status）列が含まれていないため、無効ゾーンの
除去は距離レンジと RANSAC のみに頼っている。ステータス列があるログではそちらでの
フィルタを追加した方が精度が上がる。

## 1行目：平面抽出（3.1節）の品質

### 左上 — plane distance $d_i$ [mm]

各センサーについて、**ボディ座標原点から抽出された平面までの垂直距離** $d_i = \mathbf{n}_i^T \bar{p}$
の時系列。RANSAC で外れ値を除いた後 PCA（共分散行列の固有値分解）でフィットした平面の距離である。

- **線が途切れている区間** = そのフレームで平面抽出に失敗している。原因は有効点が
  6点未満、RANSAC のインライアが足りない、または平面性が閾値を超えた（角部・開口部を
  見ている）のいずれか。
- **3センサーの $d_i$ が揃っている** なら、3つとも同じ壁面を見ている可能性が高い。
- **1つだけ大きく外れる** なら、そのセンサーが別の面（角、柱、家具）を捉えている。
- 16点を1つの距離に圧縮しているので、生の距離データよりノイズが大幅に小さい。
  この滑らかさが PCA アプローチの利点そのものである。

### 右上 — planarity $\lambda_3/\Sigma\lambda$（対数軸）

平面性スコア。共分散行列の固有値 $\lambda_1 \ge \lambda_2 \ge \lambda_3$ に対する
$\lambda_3/(\lambda_1+\lambda_2+\lambda_3)$ で、**最小固有値 = 点群が成す平面の「厚み」** を表す。

- **小さいほど良い平面**。破線が採用閾値 ε = 0.02 で、これを超えたフレームは棄却される。
- 10⁻³ 台なら非常に良好な平面、10⁻² 台に近づくと角部やノイズを疑う。
- この値は ΔR / Δt を解くときの**重み** $w_i = 1/\text{planarity}$ にもそのまま使われる。
  文書 4.3 節が述べる「観測ノイズ共分散 $V_t$ の動的適応」の簡易版に相当する。

## 2行目：フレーム間の推定量

### 左中 — Δrotation [deg/frame]（3.2節）

前フレームの法線集合 $\mathcal{N}_{t-1}$ と現フレームの $\mathcal{N}_t$ を、重み付き Kabsch
（SVD による解法）で対応付けて得た相対回転 ΔR を yaw/pitch/roll に分解したもの。

$$\Delta R = \arg\min_{R \in SO(3)} \sum_i w_i \|\mathbf{n}'_i - R\mathbf{n}_i\|^2$$

- 1フレームあたりの回転なので、20Hz なら 1 deg/frame ≒ 20 deg/s。
- 法線が張る空間のランクが 2 未満のフレームでは回転が一意に決まらないため、
  ΔR = 単位行列として採用しない（右下のランク診断パネルと対応）。
- 単発の大きなスパイクは平面抽出のミス（別の面に乗り移った）を疑う。

### 右中 — Δtranslation [mm/frame]（3.3節）

Point-to-Plane 誤差モデル $d'_i \approx d_i - \mathbf{n}_i^T \Delta t$ を重み付き最小二乗で
解いた並進量。

$$\Delta t = \arg\min_{\Delta t \in \mathbb{R}^3} \sum_i w_i \left(d'_i - (d_i - \mathbf{n}_i^T \Delta t)\right)^2$$

- 平面までの垂直距離は原点まわりの回転では変化しないため、ΔR とは独立に解ける。
- **退化方向（ランク落ち）は truncated SVD で 0 に落としてある。** それでも
  観測可能な軸に沿った成分が「漏れ」として現れることがあるので、必ず左下の
  ランク診断と併せて読む必要がある。
- 特定の軸だけ振幅が大きい場合、その軸は幾何学的に拘束されていない可能性が高い。

## 3行目：累積結果

### 左下段 — cumulative rotation [deg]

ΔR を順次掛け合わせた累積姿勢 $R_{cum} \leftarrow R_{cum} \Delta R$ を yaw/pitch/roll で表示。

- **最も信頼できる評価指標**。往復動作のログなら、終了時に開始値へ戻るかどうかが
  そのままドリフト量の指標になる。
- log41 では 34秒・ヨー往復2周期の後に yaw −0.83°、pitch −0.64°、roll −0.01° まで
  戻っており、この条件下では Kabsch 回転推定がよく機能していることが確認できた。

### 右下段 — cumulative translation [mm]（ToF vs EKF）

実線が Δt を積分した ToF 単独のオドメトリ $p_{cum} \leftarrow p_{cum} + R_{cum}\Delta t$、
破線が `stateEstimate.x/y/z`（機体の EKF 出力、mm 換算・初期値を 0 にオフセット）。

- 破線は「正解」ではない（EKF 自身もオプティカルフローと IMU のドリフトを持つ）が、
  ToF 単独推定が破綻していないかの目安になる。
- ToF 側が EKF から系統的に離れていく場合、その方向は退化軸である可能性が高い。
- 累積 Δ が累積回転と同位相で振動している場合、回転と並進のカップリングが
  退化方向に漏れているサインであり、実際の移動ではない。

## 4行目：診断

### 左最下段 — rank / count（幾何学的退化の診断）

**このパネルが並進推定を信じてよいかの判定に最も重要である。**

- `rank(Δt)`: Point-to-Plane の係数行列（法線を並べた行列）のランク。
  **3 なら XYZ 全軸が拘束されている。2 以下ならその不足分の軸は数学的に不定。**
- `rank(ΔR)`: 法線が張る空間のランク。2 未満だと回転が一意に決まらない。
- `有効センサー数`: そのフレームで前後とも平面抽出に成功したセンサーの数。

前方3センサー（yaw −45°/0°/+45°、いずれも仰角0°）だけを使う構成では、法線がほぼ
水平面内に収まるため **rank は構造的に 2 に留まる**（実際 log40・log41 では全フレーム 2）。
文書 3.3 節が指摘する廊下での退化と同じ状況で、この構成では ToF 単独オドメトリは
成立しない。上下向きのセンサー（s3, s4, s8, s9, s10）を `-s` で加えるか、
オプティカルフローと融合する必要がある。

### 右最下段 — normal azimuth [deg]

抽出された法線ベクトルのボディ座標系での方位角 $\arctan2(n_y, n_x)$。
**10度刻みの目盛に薄い灰色の点線を引いてある**ので、角度変化を直読できる。

- 機体が壁に対してヨー方向に回れば、3センサーの曲線が**同位相で同振幅**に動く。
  これが揃っていることが、回転推定が物理的に正しいことの直接的な裏付けになる。
- センサー間のオフセットは取り付け角（−45°/0°/+45°）に対応するが、**完全に一致は
  しない**。単一の平坦な壁なら3本とも同じ値になるはずで、log39 では平均相互角が
  42°（取り付け角の平均相互角 60°）残った。3センサーが別々の面や角部を見ている
  ことに加え、ゾーン格子の向き規約や FOV の実効値に校正の余地があることを示す。

## 主要パラメータ

`tof_odometry.py` 冒頭で調整できる。

| 定数 | 既定値 | 意味 |
|---|---|---|
| `FOV_DEG` | 45.0 | 正方FOV（対角65°の片辺）。実効値がずれると法線角度がスケールする |
| `D_MIN_MM` / `D_MAX_MM` | 30 / 4000 | 有効とみなす距離の範囲 |
| `RANSAC_ITERS` | 60 | RANSAC 試行回数 |
| `RANSAC_THRESH_MM` | 20.0 | 平面までの許容残差 |
| `MIN_INLIERS` | 6 | 16点中このインライア数が必要 |
| `PLANARITY_EPS` | 0.02 | 平面として採用する平面性スコアの上限 |

## 出力CSV（`--csv-out`）の列

`timestamp`, `dyaw`/`dpitch`/`droll`（フレーム間回転 [deg]）, `dx`/`dy`/`dz`（フレーム間移動 [mm]）,
`yaw`/`pitch`/`roll`（累積回転 [deg]）, `x`/`y`/`z`（累積移動 [mm]）,
`d_s<N>`（各センサーの平面距離 [mm]）, `rank_t`（Δt のランク）。
